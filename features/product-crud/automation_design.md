**Notes for T2–T4** (from `eshop-sut/frontend-admin/src/App.jsx`, read to judge what a test can reach and observe; checked on the running app in T2):

- Admin web: one page with tabs; the product tab has the form "Thêm sản phẩm mới" / "Sửa sản phẩm" (inputs with placeholders only: "Tên sản phẩm", "Giá tiền" `type="number"`, "URL Ảnh", "Mô tả", a category `<select>` with no empty option; button "Lưu sản phẩm") and the table "Ảnh / Tên SP / Giá / Hành động" with "Sửa" and "Xóa" per row. No `<label>`, so DT-23 has nothing with `*` to find (HW02 BUG-33); locators by placeholder or role in T2.
- Only the name is `required`; the price field has no `min` and no `step` (so `-50000` and `0` are typed in, the browser may block `250000.5` and `abc`). The token is stored in `localStorage` `adminToken` and sent by axios; the login refuses a non-admin with the `alert` "Bạn không phải là admin!".
- An add reloads the list from the API (`App.jsx:117–118`). An edit shows the `alert` "Cập nhật thành công!" and then copies the edited name to **every row** of the list without reloading (`App.jsx:109–115`). HW02 saw "Cập nhật thành công" and the same name on all 6 rows during the DT-01 run, so BUG-34 shows after an edit; after an add alone, DT-24 may pass (decision 2). A failed save shows the `alert` "Lỗi lưu sản phẩm: …" (a dialog, not a message above the button).
- Independence: each Web / API test creates its own P through the API (no "run after every other TC", no shared P); the new product is found by the id the API returns or by the ids before / after, not by the count alone (T3). "In Vietnamese" in the FR-22 oracle of DT-09, 12, 14, 17 … 19 cannot be checked by a script: T3 marks it `<CONFIRM>`.
